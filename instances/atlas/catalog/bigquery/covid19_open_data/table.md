## What's in this table

One row per (location, date). Key columns: `location_key`, `date`,
`new_confirmed`, `cumulative_confirmed`, `new_deceased`, `cumulative_deceased`,
`new_tested`, `population`, `subregion1_name` (state/province),
`subregion2_name` (county), `country_name`.

## Notes for query planning

- `location_key` encodes the place hierarchy (e.g. `US_CA_06001` = Alameda
  County, CA). Filter on `subregion2_name` + `subregion1_code` when the
  question names a county in plain English rather than a location key.
- The table is partitioned by `date` — always include a date filter to keep
  scans small; an unfiltered `SELECT *` over this table is exactly the kind
  of query the byte cap exists to catch.
- Reporting cadence and definitions vary by source jurisdiction; treat single-
  day spikes/dips as reporting artifacts rather than real changes unless the
  question is specifically about reporting anomalies.
